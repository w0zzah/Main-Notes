


### How to choose pacer rates

Say you have two tasks, one at 250Hz and the other at 100 Hz. Find the smallest rate where PACER_RATE / 250Hz and PACER_RATE / 100Hz are both whole numbers. 

### display.h

**display_update(game_state, board_role, paddle_row, \*ball):**
Loops over each of the columns checking the state of the game and displaying the required LED's


### THE way it all works

Every stage is a value of the game_phase_t enum stored in game.he. Game_update runs once per loop and does whatever the current phase says.

| Stage (phase)                                         | What the player sees                                        | What happens in the code                                                                                                                                                                | Leaves when                                                                                                                                 |
| ----------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Handshake** (`PHASE_HANDSHAKE`)                  | Paddle only                                                 | `game_update` counts ticks and returns `SEND_START` every `STARTUP_RETRY` ticks. `main.c` turns that into an IR `START` byte.                                                           | An `ACK` arrives (we serve first, go to Aim), or a `START` arrives (we send `ACK`, go to Waiting).                                          |
| **2. Waiting** (`PHASE_WAITING`)                      | Paddle only                                                 | Nothing runs. The board only reacts to IR messages.                                                                                                                                     | A `BALL` message arrives (go to Flight), or a `LOST` message arrives (we score).                                                            |
| **3. Receiving** (`PHASE_FLIGHT`, ball heading right) | Ball crossing from the left, paddle on the right            | The ball enters at column 0. `ball_update` steps it every `ball_step_ticks()`. Every loop, `game_update` checks whether the ball is in the paddle column and the paddle covers its row. | **Caught:** go to Aim, ball held in front of the paddle. **Missed:** the ball passes the paddle, so the opponent scores and we send `LOST`. |
| **4. Aim** (`PHASE_AIM`)                              | Ball plus a 2-LED line swinging left, middle, right, middle | `aim_dir` changes every `AIM_SWING_TICKS`. The paddle is frozen.                                                                                                                        | Navswitch push locks the direction.                                                                                                         |
| **5. Power** (`PHASE_POWER`)                          | The whole matrix fills bottom to top and back               | `power_level` ping-pongs 0 to 6, one step per `POWER_STEP_TICKS`.                                                                                                                       | A second push fires the ball with the current level.                                                                                        |
| **6. Shooting** (`PHASE_FLIGHT`, ball heading left)   | Ball leaves the paddle at the aimed angle and speed         | Same flight code. When the column goes below 0 the event is `TRANSFER`, and `comms_send_ball` sends row, direction and power.                                                           | The ball leaves, and we go to Waiting.                                                                                                      |
| **7. Scoring**                                        | Blue LED flashes on the winner’s board                      | On a `LOST` message, `my_score++` and `flash_ticks = FLASH_TICKS`. When we miss, `opp_score++` and the loser goes to Aim to serve.                                                      | At `WIN_SCORE` points, go to Won or Lost.                                                                                                   |
| **8. Game over** (`PHASE_WON` / `PHASE_LOST`)         | W or L                                                      | `display.c` draws the letter. The loser presses BUTTON1 to send `GO` for a rematch.                                                                                                     | `GO` resets both scores.                                                                                                                    |
