Graph Fundamentals

Core Definitions

A graph is an ordered pair G = (V, E) where V is the set of vertices and E is the set of edges. We use n = |V| (number of vertices) and m = |E| (number of edges). The fundamental bound is m ≤ n².

Undirected graph
Edges are unordered pairs {u, v}. Going from u to v also allows v to u. Symmetric relationship.
Directed graph
Edges are ordered pairs (u, v). Edge from u to v does not imply v to u. One-way.
Weighted graph
A triple (V, E, W) where W: E → ℝ assigns a real number (weight) to each edge.
Sparse vs dense
Sparse: m ∈ O(n). Dense: m ∈ Θ(n²). Most real-world graphs are sparse.

Graph String Format

This format is used in all quizzes and the test. Memorise it.

# Header: [D|U] n [W] # D = directed, U = undirected, n = number of vertices # W = weighted (optional third field) # Each remaining line: u v [weight] U 4 # undirected, 4 vertices (0..3), unweighted 0 1 3 1 0 3 D 2 W # directed, 2 vertices, weighted 0 1 -5 1 0 8
Key: In an undirected graph, each edge appears once in the text (e.g., either "0 1" or "1 0", not both). But in the adjacency list, it appears in both Adj[0] and Adj[1].

Data Structures: Adjacency Matrix vs List

Operation Adjacency Matrix Adjacency List
Check edge (i,j) exists Θ(1) O(n)
Add / delete an edge Θ(1) O(n)
Iterate edges from vertex Θ(n) O(degree)
Iterate ALL edges Θ(n²) Θ(n + m)
Space Θ(n²) Θ(n + m)
Why adjacency lists win: Graph traversal iterates over all edges. For sparse graphs (most real-world cases), m ≪ n², so Θ(n+m) is much better than Θ(n²). Adjacency lists are the default for BFS/DFS/Prim/Dijkstra.

Adjacency List in Python

# Weighted undirected example: "U 4 W / 3 1 -4 / 1 0 7" adj = [ [(1, 7)], # vertex 0: edge to 1 with weight 7 [(3, -4), (0, 7)], # vertex 1: edges to 3 (w=-4) and 0 (w=7) [], # vertex 2: no edges [(1, -4)] # vertex 3: edge to 1 with weight -4 ] # For unweighted: use (neighbour, None) — e.g., [(1, None), (3, None)]

Key Structural Concepts

Path
A sequence of vertices (v₀, v₁, …, vₖ) where each consecutive pair is an edge, and no edge is used more than once. Length = number of edges = k.
Cycle
A path of length ≥ 1 where source = destination. A graph with at least one cycle is cyclic; without cycles = acyclic. A directed acyclic graph is a DAG.
Component
A maximal connected subgraph of an undirected graph. Every vertex has a path to every other vertex in the same component.
Tree / Forest
A tree = rooted graph where every vertex has exactly one path to the root. A forest = graph where every component is a tree. Represented by a parent array.

Strongly Connected Graphs (Directed)

A directed graph is strongly connected if there is a path between every ordered pair of vertices.

Efficient test using the hub algorithm:

1
Run BFS/DFS from an arbitrary vertex h on G. If any vertex is undiscovered → not strongly connected.
2
Construct GT (transpose: reverse all edges).
3
Run BFS/DFS from h on GT. If any vertex is undiscovered → not strongly connected. Otherwise → is strongly connected.
Why it works: If h can reach everywhere in G AND everywhere can reach h (shown by h reaching everywhere in GT), then every vertex can reach every other vertex through h. Complexity: O(n + m)

BFS & DFS

Three Vertex States

U Undiscovered
Not yet encountered. Initial state of all vertices.
D Discovered
Encountered but not fully processed yet. Being actively explored.
P Processed
Fully explored. All neighbours have been considered.
Transitions
U → D when first encountered. D → P when all neighbours explored.

BFS — Breadth-First Search

Uses a queue (FIFO). Discovers vertices in order of increasing distance from the start.

def bfs_tree(adj, s): n = len(adj) state = ['U'] * n parent = [None] * n Q = deque() state[s] = 'D' Q.append(s) while Q: u = Q.popleft() # dequeue from front for v, _ in adj[u]: if state[v] == 'U': state[v] = 'D' parent[v] = u Q.append(v) state[u] = 'P' return parent

DFS — Depth-First Search

Uses a call stack (LIFO) via recursion. Explores as deep as possible before backtracking.

def dfs_tree(adj, s): n = len(adj) state = ['U'] * n parent = [None] * n state[s] = 'D' dfs_loop(adj, s, state, parent) return parent def dfs_loop(adj, u, state, parent): for v, _ in adj[u]: if state[v] == 'U': state[v] = 'D' parent[v] = u dfs_loop(adj, v, state, parent) # recurse deep first state[u] = 'P' # processed only after all descendants
DFS vs BFS key difference: In BFS, use a queue and popleft(). In DFS, use recursion (implicit call stack). You can also implement DFS iteratively by replacing the queue with a stack and using pop() instead of popleft().

Complexity (both BFS and DFS)

Time: O(n + m) = O(max(n, m))

Initialisation is Θ(n). Each vertex is discovered at most once. Each edge is examined at most once (O(m) total over all vertices). Therefore O(n + m).

BFS Application: Shortest Path (unweighted)

Since BFS visits vertices in order of distance from the source, the path in the predecessor tree from root s to any vertex t is the shortest path (fewest edges) in the graph.

def tree_path(parent, s, t): if s == t: return [s] else: return tree_path(parent, s, parent[t]) + [t]

Connected Components

Repeatedly run BFS/DFS from any undiscovered vertex until all vertices are processed. Each BFS/DFS call discovers one component.

DFS Application: Topological Sort (DAGs only)

1
Run modified DFS over all vertices. As each vertex is marked Processed, append it to finish_order.
2
Return reverse(finish_order) as the topological ordering.
Why it works: If edge (u, v) exists, then v must finish (be Processed) before u. So v appears before u in finish_order, and u appears before v after reversing — exactly what topological sort requires.

DFS Application: Cycle Detection

Directed graph
During DFS, if examining edge (u, v) and v is already Discovered (still on the call stack), then there's a cycle — we've found a path from v back to itself.
Undirected graph
Same idea, but ignore the edge (u, v) where v = parent[u] — that's just the tree edge going backwards, not a cycle (a cycle must have length ≥ 1 and not reuse edges).

Comparing BFS and DFS

BFS (Breadth-First)
DFS (Depth-First)
  • Uses a queue (FIFO)
  • Discovers by increasing distance
  • Good for shortest paths (unweighted)
  • Good for connected components
  • Iterative implementation natural
  • Parent array = BFS tree (shortest paths from s)
  • Uses call stack (recursion/LIFO)
  • Goes deep first, then backtracks
  • Good for topological sort
  • Good for cycle detection
  • Good for strong connectivity
  • Vertex stays Discovered until ALL descendants processed

Prim's Algorithm & Dijkstra's Algorithm

These two algorithms are almost identical in structure. The only difference is what "distance" means and how it's updated. Understanding this connection is key to understanding both.

Prim's Algorithm — Minimum Spanning Tree

Finds a spanning tree with the minimum total edge weight. Grows a tree by always adding the cheapest edge from the tree to a non-tree vertex.

def prim(adj, s): n = len(adj) in_tree = [False] * n distance = [float('inf')] * n parent = [None] * n distance[s] = 0 while not all(in_tree): u = next_vertex(in_tree, distance) in_tree[u] = True for v, weight in adj[u]: if not in_tree[v] and weight < distance[v]: # ← KEY LINE distance[v] = weight # just the edge weight parent[v] = u return parent, distance def next_vertex(in_tree, distance): # Return the closest non-tree vertex min_dist = float('inf') u = -1 for i, in enumerate(in_tree): if not in_tree[i] and distance[i] < min_dist: min_dist = distance[i] u = i return u

Dijkstra's Algorithm — Shortest Path Tree

Finds the shortest path distance (sum of weights) from source s to every other vertex. The only change from Prim's is how distance is updated.

def dijkstra(adj, s): n = len(adj) in_tree = [False] * n distance = [float('inf')] * n parent = [None] * n distance[s] = 0 while not all(in_tree): u = next_vertex(in_tree, distance) in_tree[u] = True for v, weight in adj[u]: if not in_tree[v] and distance[u] + weight < distance[v]: # ← KEY LINE distance[v] = distance[u] + weight # path distance from source parent[v] = u return parent, distance
Prim's (MST)
Dijkstra's (Shortest Path)
Goal: Minimum total tree weight

distance[v] = cheapest edge weight from tree to v

Update condition:
weight < distance[v]

Update value:
distance[v] = weight

Works on any undirected weighted graph
Goal: Shortest path from source s to all vertices

distance[v] = cumulative path distance from s to v

Update condition:
distance[u] + weight < distance[v]

Update value:
distance[v] = distance[u] + weight

⚠️ Fails with negative edge weights

Complexity

ImplementationTime Complexity
Basic (array scan for next vertex)O(n²)
With heap-based priority queueO(m + n log n)

Derivation (basic): While-loop runs n times. Each Next-Vertex scan is O(n) → O(n²) total. For-loop body runs O(m) total across all iterations. Since m ≤ n², overall is O(n²).

Important Distinctions

MST ≠ Shortest Path Tree. A path from the root of an MST to another vertex is not necessarily the shortest-distance path in the graph. They can differ! MST minimises total tree weight; shortest path tree minimises path distances from the root.
Dijkstra fails with negative weights. It assumes that once a vertex is added to the tree, its shortest distance is finalised. Negative edges can break this assumption.
MST uniqueness: MSTs are not necessarily unique. However, all MSTs of a graph have the same total weight.

Backtracking

Backtracking is an algorithmic technique that generates all (or some) solutions by performing a DFS on an implicit tree of candidate solutions.

Core Idea

Candidates are built incrementally. You start with an empty (or root) candidate and extend it step by step. If a partial candidate cannot possibly lead to a valid solution, you "backtrack" (return early) and try a different branch.

The General Algorithm

def dfs_backtrack(candidate, input_data, output): if is_solution(candidate, input_data): add_to_output(candidate, output) else: for child in children(candidate, input_data): dfs_backtrack(child, input_data, output)

The Four Functions You Must Implement

is_solution(candidate, input)
Returns True if candidate is a complete, valid solution. This is the base case — equivalent to reaching a leaf of the implicit tree.
Example (binary numbers): return len(candidate) == desired_length
children(candidate, input)
Returns a list of candidates that extend the current candidate by one step. These are the children in the implicit tree.
Example (binary numbers): return [candidate + "0", candidate + "1"]
add_to_output(candidate, output)
Adds the valid solution to the results list.
Example: output.append(candidate)
should_prune(candidate)
Returns True if we can determine this subtree will never contain a solution. Pruning — add this check at the start of dfs_backtrack to improve performance.
Example (at most four 1s): return candidate.count("1") > 4

Complete Example: Binary Numbers of Length n

def is_solution(candidate, desired_length): return len(candidate) == desired_length def children(candidate, desired_length): return [candidate + "0", candidate + "1"] def add_to_output(candidate, output): output.append(candidate) def dfs_backtrack(candidate, desired_length, output): if is_solution(candidate, desired_length): add_to_output(candidate, output) else: for child in children(candidate, desired_length): dfs_backtrack(child, desired_length, output) def binary_numbers(n): solutions = [] dfs_backtrack("", n, solutions) return solutions

The Implicit Tree (n = 3)

The candidates form a tree. Each node is a candidate; edges connect a candidate to its extensions.

"" / \ "0" "1" / \ / \ "00" "01" "10" "11" / \ / \ / \ / \ 000 001 010 011 100 101 110 111 ↑ Solutions are all the leaf nodes ↑

Pruning with should_prune

def dfs_backtrack(candidate, input_data, output): if should_prune(candidate): # ← check this FIRST return if is_solution(candidate, input_data): add_to_output(candidate, output) else: for child in children(candidate, input_data): dfs_backtrack(child, input_data, output)
Pruning is crucial for performance. should_prune(candidate) must return True if no descendant of candidate can be a valid solution. This cuts off entire subtrees and can drastically reduce runtime (e.g., in Sudoku: prune if any constraint is already violated).

Complexity Analysis

Asymptotic Notation

O(g) — Upper bound
f grows at most as fast as g. There exist constants c > 0 and x₀ such that f(x) ≤ c·g(x) for all x ≥ x₀.
Ω(g) — Lower bound
f grows at least as fast as g. There exist constants c > 0 and x₀ such that c·g(x) ≤ f(x) for all x ≥ x₀.
Θ(g) — Tight bound
f grows at exactly the same rate as g. Θ(g) = O(g) ∩ Ω(g). Both upper and lower bounds are g.
Key algebraic rule
O(g₁ + g₂) = O(max(g₁, g₂)) — Only the dominant term matters.
e.g. O(n + m) where m ≤ n² means this equals O(n²) in the worst case.

Complexity Hierarchy (slowest → fastest growth)

O(1) ⊂ O(log n) ⊂ O(n) ⊂ O(n log n) ⊂ O(n²) ⊂ O(2ⁿ) ⊂ O(n!)

Deriving Prim/Dijkstra Complexity Step-by-Step

1
While-loop runs n times — once per vertex (each iteration adds exactly one vertex to the tree).
2
next_vertex scan is O(n) — must check all n vertices to find the minimum distance non-tree vertex.
3
For-loop (across ALL while iterations) is O(m) — each edge (u,v) is examined at most once (when u is added to the tree).
4
Total: O(n × n) + O(m) = O(n²) + O(m) = O(n²) since m ≤ n².

Practice Quiz

Test your knowledge. Reveal the answer only after you've thought it through.

Q1. In Prim's algorithm, what does distance[v] represent?
✅ B. In Prim's, distance[v] is the weight of the cheapest single edge that connects v to the growing tree. This is what distinguishes it from Dijkstra's, where distance[v] = total cumulative path cost from s to v.
Q2. Why does Dijkstra's algorithm fail with negative edge weights?
✅ C. Dijkstra's greedy assumption is: once a vertex u is added to the tree, distance[u] is finalised. With negative weights, a later path through a negative edge could give a shorter distance to u — but the algorithm has already committed to the wrong answer.
Q3. What is the time complexity of BFS on a graph with n vertices and m edges?
✅ B. O(n + m). Initialisation is Θ(n). Each vertex is enqueued/dequeued at most once. Each edge is examined at most once (for directed: once per edge; for undirected: once from each endpoint = 2m total, still O(m)). Total: O(n + m).
Q4. During DFS on a directed graph, when we examine edge (u, v) and v is in state Discovered, what can we conclude?
✅ B. In DFS, a vertex is Discovered but not yet Processed means it's currently on the call stack — we haven't finished exploring it. If we find an edge (u, v) where v is Discovered, that means v is an ancestor of u in the DFS tree, so we've found a path from v to v (a cycle). This is the cycle detection algorithm.
Q5. In a backtracking algorithm, the should_prune function should return True when:
✅ B. Pruning cuts off an entire subtree. should_prune must guarantee that no leaf in this subtree is a valid solution. For example in Sudoku: if a row already has two 5s, no completion of that partial board can be valid — prune.
Q6. Which graph representation is generally preferred for BFS and DFS, and why?
✅ B. BFS and DFS iterate over all edges. Adjacency list does this in Θ(n + m). Adjacency matrix requires visiting all n entries per vertex = Θ(n²) total. For sparse graphs (m ≪ n²), adjacency lists are much more efficient. Space-wise lists also win: Θ(n + m) vs Θ(n²).
Q7. What is the key structural difference between an MST and a shortest-path tree?
✅ B. A shortest-path tree is specific to one source vertex — the path from root to any vertex v is the shortest path in the graph. An MST minimises total tree weight, but the path from its root to a vertex might not be the shortest distance path. They solve different problems and can differ significantly.
Q8. Given parent = [None, None, 1, 2, 5, 1, 1], what is the shortest path from vertex 1 to vertex 4?
✅ C: 1 → 5 → 4. Trace backwards: parent[4] = 5, parent[5] = 1, parent[1] = None (root). So path backwards is 4 ← 5 ← 1, which forwards is 1 → 5 → 4.
